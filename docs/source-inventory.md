# Data Source Inventory

This document defines the raw data sources for the telecom customer usage pipeline.

## Source Summary

| Source | Type | Raw landing folder | Main use |
| --- | --- | --- | --- |
| Synthetic Telco Churn sample | Generated CSV | `data/samples/` | Safe fresh-clone demonstration |
| IBM Telco Customer Churn | Verified CSV download | `data/raw/customer_churn/` | Full customer profile, services, billing, and churn analysis |
| Generated Daily Usage Files | Generated CSV | `data/raw/daily_usage/` | Simulated daily calls, SMS, data usage, and revenue |
| UCI SMS Spam Collection | Text/CSV download | `data/raw/sms_messages/` | SMS text records for message validation and text processing |
| World Bank Telecom Indicators | Public API JSON | `data/raw/world_bank_telecom/` | External country-level telecom enrichment |

## 1. Synthetic Telco Churn Sample

- Source system: deterministic generator in `scripts/generate_sample_data.py`.
- Access method: committed 100-row CSV or `python scripts/setup_data.py --source sample`.
- Expected file name: `data/samples/telco_customer_churn_synthetic.csv`.
- Identifiers: fictional values prefixed with `SYNTH-`.
- Pipeline purpose: demonstrate every local pipeline stage without downloading or redistributing external customer data.
- Reproducibility: seed `42`, exact 21-column input schema.
- Privacy note: all rows are generated and contain no real customer records.

## 2. IBM Telco Customer Churn

- Source system: public IBM sample dataset from IBM's [`watsonx-ai-samples`](https://github.com/IBM/watsonx-ai-samples/blob/master/cpd4.5/data/customer_churn/WA_FnUseC_TelcoCustomerChurn.csv) repository.
- Access method: `python scripts/setup_data.py --source ibm`.
- Expected file name: `telco_customer_churn.csv`.
- Expected refresh: one-time baseline dataset.
- Raw folder: `data/raw/customer_churn/`.
- Expected fields: `customerID`, demographics, subscribed services, contract, payment method, monthly charges, total charges, `Churn`.
- Pipeline purpose: build customer-level churn and revenue features.
- Initial quality checks:
  - `customerID` must not be null.
  - `customerID` should be unique.
  - `MonthlyCharges` should be numeric and non-negative.
  - `Churn` should contain expected categories only.
- Privacy note: this is public sample data, but the pipeline treats customer identifiers as sensitive.
- Supply-chain controls: the setup script verifies the pinned SHA-256 checksum, exact schema, and expected row count before installation.
- Redistribution rule: the downloaded CSV remains ignored and is not committed to this repository.

## 3. Generated Daily Usage Files

- Source system: local generator script that simulates telecom operational usage.
- Access method: generated by this project.
- Expected file name pattern: `daily_usage_YYYY_MM_DD.csv`.
- Expected refresh: daily.
- Raw folder: `data/raw/daily_usage/`.
- Expected fields: `usage_date`, `customerID`, `region`, `calls_count`, `sms_count`, `data_mb`, `revenue`.
- Pipeline purpose: simulate daily customer activity from billing/network systems.
- Initial quality checks:
  - `usage_date` must be a valid date.
  - `customerID` must not be null.
  - Usage and revenue values must not be negative.
  - Duplicate rows for the same `usage_date` and `customerID` should be flagged.
- Privacy note: generated data must not contain real phone numbers, names, addresses, or account numbers.

## 4. UCI SMS Spam Collection

- Source system: UCI Machine Learning Repository.
- Access method: manual download for the first version.
- Expected file name: `sms_spam_collection.csv`.
- Expected refresh: one-time baseline dataset.
- Raw folder: `data/raw/sms_messages/`.
- Expected fields: `label`, `message`.
- Pipeline purpose: validate and process message-level telecom text data.
- Initial quality checks:
  - `label` must be present.
  - `message` must not be empty.
  - Duplicate messages should be measured.
  - Very short or malformed messages should be flagged.
- Privacy note: do not add real customer SMS records to this project.

## 5. World Bank Telecom Indicators

- Source system: World Bank Indicators API.
- Access method: HTTP API, no API key required.
- Expected file name pattern: `world_bank_telecom_indicators_YYYY_MM_DD.json`.
- Expected refresh: monthly or manual.
- Raw folder: `data/raw/world_bank_telecom/`.
- Example indicators:
  - `IT.CEL.SETS.P2`: mobile cellular subscriptions per 100 people.
  - `IT.NET.USER.ZS`: individuals using the internet as a percentage of population.
- Pipeline purpose: enrich the telecom case study with external country-level market context.
- Initial quality checks:
  - API response must not be empty.
  - `country`, `date`, `indicator`, and `value` should be present.
  - Year values should be valid.
- Privacy note: this source is public country-level data and does not contain customer PII.

## Raw Data Rules

- Store original files in `data/raw/` without manual cleaning.
- Never overwrite a raw file silently.
- Use source-specific folders so each dataset can be validated independently.
- Do not commit large raw datasets or sensitive data to Git.
- Keep sample data small enough for local development.

## Safe Setup

The setup utility writes to a temporary file, validates it, and only then moves
it into the raw landing path. Existing input is preserved unless `--force` is
provided explicitly. The synthetic source is the default and requires no network
access; the IBM source is optional and downloaded directly from IBM.
